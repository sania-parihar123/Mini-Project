# 13 User Interface (Streamlit)
Status: agreed
Source: Part 5.1, Part 5.1a, Section 10.9 [BASELINE + PROPOSED]

## Purpose
Deliver the interactive Streamlit user interface faithfully reflecting the clickable SaaS reference prototype, supporting all workspace pages, document workflows, real backend communication, and role actions.

## Requirements
- SPEC-13-01 The UI shall maintain the visual structure of `processfoundry_ai_professional_clickable_prototype.html`:
  - Deep navy persistent sidebar (`#101F36`) with brand mark, section headers, active navigation pills, and system health status.
  - Sticky topbar (`#FFFFFF`) with breadcrumbs, user avatar initials, user name, current project role, and Sign out button.
  - Light grey-blue background (`#F5F7FB`), white cards (`#FFFFFF`) with subtle line borders (`#E5EAF1`), and blue primary buttons (`#3568F5`).
- SPEC-13-02 The UI shall support split-screen Sign In and Create Account views for unauthenticated visitors. Signed-out users shall be restricted to Page 0.
- SPEC-13-03 The UI shall provide the following workspace pages:
  1. `My Projects`: Summary metrics, pending invitations banner, recent project cards with status pills and Open action, and Create Project CTA.
  2. `Create a Project`: Project creation form with name, process type, description, department, and role selection.
  3. `Project Overview`: Project status, stage summary, team members list, and first-class **Evidence & Documents** section with drag-and-drop file upload, file list, parse status, and Start Analysis trigger.
  4. `Waiting for Me`: Focused queue showing only questions routed to the user's role in their projects.
  5. `Sources & Documents`: Document management, sections preview, parse warnings, and re-upload.
  6. `Discovery (As-Is)`: Interactive step list/table with actors, inputs, outputs, unknowns, and evidence links.
  7. `Questions & Rules`: Question answering panel showing conflicting quotes side by side, AI suggestions, answer input, and confirm/unknown actions; rules list with status pills.
  8. `Redesigned Process (To-Be)`: Redesigned flow with automation classification (deterministic, AI, human, hybrid) and human approval actions (Approve / Request Changes / Reject).
  9. `Documents & Artifacts`: Tabs for BRD, PRD, FRD, SRS, architecture, data model, test plan, UAT pack, and Markdown download.
  10. `Workflow & Traceability`: Visual workflow preview and interactive evidence-to-test traceability matrix.
  11. `Team & Invitations`: Active members table, pending invitations with resend/revoke, and invite teammate form.
  12. `Audit Log`: Chronological immutable audit event log with SHA-256 hash chains.
- SPEC-13-04 The UI shall communicate with the FastAPI backend over HTTP/REST using the signed bearer token stored in `st.session_state`.
- SPEC-13-05 The UI shall never use mock data or fake success messages in place of real backend operations.

## Acceptance criteria
- AC-13-01 (covers SPEC-13-01/02) Given an unauthenticated visitor, the app renders the split-screen sign in / sign up view with brand messaging and form fields.
- AC-13-02 (covers SPEC-13-03) Given a signed-in user opening a project, the Project Overview displays the first-class Evidence & Documents upload section and live project team.
- AC-13-03 (covers SPEC-13-04/05) Given a file uploaded in Streamlit, it is posted to `/api/projects/{id}/documents`, parsed, and rendered with genuine section counts.
